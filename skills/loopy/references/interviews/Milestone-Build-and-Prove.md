# Milestone Build and Prove

Use this internal route when a Human asks to implement or continue a ready Milestone, run a planned evaluation, or inspect Build/Proof status. Never expose this route as a separate skill or command.

Load the committed Definition, current ready Plan, Change state, and synchronized project views. Apply the shared after-response move-selection loop. Inherit settled meaning; ask only for the exact execution authority or unavailable judgment required now.

Before product mutation, establish one active-session grant naming the ready Work Units, participant and represented responsibility, implementation workspace and fingerprint, source fingerprint, tools, permitted local source-control operations, external systems, activated evaluation budget, and applicable model/cost choices. A clear request may provide these together. Reuse the grant only while every anchor and scope remains unchanged. Never infer branch, worktree, commit, external mutation, push, PR, merge, tag, deployment, publication, or Release permission from implementation intent.

Immediately before assigning an orchestrator, builder, focused evaluator, or final evaluator, derive a tentative workload assessment from existing Plan meaning and current availability. Recommend an actually available host/model with a short basis; ask only for genuinely missing preferences. Record the actual host, model, settings/profile, and whether it is merely available, recommended, tested, or release-qualified. Evaluator provenance also records a fresh task or clean context and a separate clean disposable evaluation workspace while retaining the exact implementation source/workspace anchors. Label an untested recommendation unverified and make no support claim. Assign tasks only while the exact Build session is active, never while interrupted, blocked, paused, or ready for Demonstration.

Execute eligible Work Units in stable Plan order by default. A later eligible Work Unit may start early only when the current Plan explicitly places it in a safe parallel group with the first eligible unit. Concurrent work requires that claim plus current conflict-free ownership, source, workspace, file/interface/schema/environment, and integration checks. Give an incomplete Work Unit only one active builder assignment; never silently duplicate or replace its ownership. Stop for explicit coordination instead. Missing dependency data never means safe. Record partial or uncertain effects truthfully and stop.

Use only Plan evaluation boundaries. Builder checks may run continuously. Freeze a new exact candidate at a justified focused checkpoint or the mandatory final integrated boundary. Give an independent evaluator the authoritative charter and neutral-unproven posture, without builder coaching or expected answers. A failed correction creates lineage only when its exact source or workspace snapshot changed from the failed parent; an unchanged resubmission consumes no candidate, attempt, cycle, or budget. Preserve every failed result. Stop on pass. At exhaustion, pause with the latest candidate, evidence, findings, and one decision. Increasing a limit requires explicit Human judgment.

Publish `Proof.md` at explicit request, meaningful failure/block/pause, status/reporting, or ready-for-Demonstration boundaries—not after every ordinary update. Evidence is attributed raw observation; failed evidence cannot support a claim. Proof maps claims and every applicable acceptance criterion and planned check to inspectable evidence. Final PASS coverage must use passing evidence produced by the assigned independent final evaluator for that exact frozen candidate; prior builder evidence cannot substitute. Ready for Demonstration requires final independent integrated PASS on the exact candidate with complete declared coverage. It is not Demo, Confirmation, human Acceptance, completion, or Release.

Use [the Build and Prove Engine reference](../engine/Milestone-Build-and-Prove-Apply.md) for formal operations. The Engine validates declarations and provenance; the Host owns implementation judgment, semantic containment, recommendation quality, and whether evidence supports a claim.
