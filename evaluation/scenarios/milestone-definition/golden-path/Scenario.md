# Golden Product → Engineering/Roadmap → Milestone Definition

## Purpose

Carry the versioned Harbor Product fixture through confirmed Product meaning, confirmed Engineering guidance, classified Roadmap dependencies, atomic candidate selection, separate Definitions, and independent Planned-Milestone commitments. This is a controlled builder scenario, not independent proof of Host interview quality.

## Setup

- Exact source candidate and commit are recorded by the runner.
- Start in a fresh disposable copy of `evaluation/scenarios/product-start/large-mixed-project/fixture`.
- Apply the versioned Product setup, Engineering examples, and explicit Roadmap dependency classifications used by the automated Slice 4 test.
- Grant only the fixture context already authorized by those earlier stages.

## Path and observations

1. Select independently understandable candidates atomically, then enter Definition in ordinary language.
2. Verify one collision-safe readable `Definition.md` per selected candidate and no Definition files before successful selection.
3. Inherit established outcome/dependency meaning and ask only current Definition gaps.
4. Establish observable acceptance boundaries, distinguish implementation dependencies, declare required perspectives, and record Host coherence without claiming Engine semantic judgment.
5. Review each current revision. Let the final required response explicitly commit more than one named ready Definition; verify separate receipts and history entries.
6. Leave an unready named Definition unchanged while committing another ready named Definition. Never include an unnamed Definition.
7. Verify `LOOPY.md`, `Roadmap.md`, and Definition files agree, show one next action, retain readable source provenance, and create no Plan, Proof, Demo, Release, worktree, implementation, deployment, or publication artifact.

## Pass boundary

The deterministic path passes when every formal transition and view invariant holds. It does not establish that a live Host chose good questions, understood meaning, or stopped at the right semantic boundary; that requires an independent preserved multi-turn run.
