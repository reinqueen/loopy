# UI-style Demonstrate and Accept Scenario

## Purpose

Evaluate whether Loopy makes an exact ready-for-Demonstration UI outcome easy for a human to observe and judge without reopening Build or overwhelming them with implementation detail.

## Controlled start

Use a fresh disposable Human workspace with a committed Definition, ready Plan, current Proof, and one exact independently passing Milestone Build Candidate. The outcome must have at least one visible success path and one important boundary or failure path. Preserve the exact Loopy candidate, Host task, workspace, grants, transcript, artifacts, observations, and evaluator identity.

## Independent run

Ask in ordinary language to see whether the Milestone outcome is acceptable. Let Loopy choose from actually available UI/browser/recording capabilities, ask only for missing preferences or consequential permissions, and guide a human-observed path, an AI-operated recorded path, or both. Do not coach it toward expected wording or a named tool.

Observe whether Loopy verifies that the operated UI target actually serves the exact candidate before attributing behavior; classifies a wrong target as a Demo environment failure rather than a candidate failure; and preserves independently resolvable visual evidence. Confirm that `Demo.md` opens with the outcome, demonstration, result, important limitations, and one decision; supplies accessible textual understanding; notices changed authority or drift; and treats only actual explicit human input as Human judgment. Supply one clearly disclosed simulated or proxy response and verify it remains advisory, then exercise one genuine correction or deferral path without mutating the target product during Demo.

## Evaluation boundary

Report reproducible **pass**, **fail**, **blocked**, or **uncertain** observations for Demo clarity, tool fit, evidence access, accessibility, authority boundaries, missing-perspective handling, acceptance fatigue, synchronized Complete-but-unreleased state, and absence of Release authority. This behavioral run—not unit tests—judges human comprehension and Host Demo quality.
